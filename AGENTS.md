- Отвечаешь только на русском, по делу, чётко и ёмко.

## Назначение

ElementsUI - библиотека `poe-svelte-ui-lib` (npm, MIT): компоненты и смарт-виджеты, тема, языки RU/EN/ZH, ядро протоколов и мастер-словарь команд. Что внутри, как пользоваться, разработка и выпуск - в `README.md`, читать его перед работой.

Библиотека - часть стека xPOE-DevStack, общая карта проектов и сквозной протокол - в `.knowledgebase/Overview.md` (раздел о месте в стеке) и справочниках соседних проектов `D:/Projects/{Проект}/KnowledgeBase-{Проект}.md`, формат пакета - `src/lib/protocols/PROTOCOL.md`.

## Главные границы

- Библиотеку используют DevCloud, веб-интерфейс прошивок ProdFactory-ESP и DevTerminal. Любая правка компонента, темы или протокола сразу видна во всех трёх: проверяй, что их не ломаешь.
- Компонент только показывает и сообщает (пропсы и колбэки). Сеть и состояние устройств - в приложении.
- WebSocket-конверт везде `{HAR, VAL}` (`encodeWsEnvelope`/`decodeWsEnvelope`), имена команд в провод не уходят.
- `src/lib/protocols/` - единственный источник протокола и кодека. `dictionary.yaml` - мастер-словарь (коды 0-4095 - устройства, 7000-7999 - команды облака DevCloud): новый аргумент сначала сюда, потом копии в `.framework/Dictionary.yaml` и `api_har.h` обоих фреймворков. После правки протоколов - `npm run TestProtocols`.
- Описание компонента для программиста - в панели свойств конструктора (кнопка (i)), не в интерфейсе пользователя.
- Внутри библиотеки импорты относительные, витрина импортирует через `#lib`.

## Узкий экран

- Компонент подстраивается под ширину своего места, а не окна: корень виджета - `@container`, внутренние колонки - `@sm:`/`@md:`/`@xl:`. Классы `sm:`/`md:` (ширина окна) в компонентах не использовать: в узкой ячейке на компьютере и в рамке «Телефон» они дают сжатые поля. Исключение - размеры текста `TextField` на телефоне (`max-sm:`).
- Шапка виджета (`WidgetHeader`) - всегда одна строка: уже 640 px отдаёт `right(narrow)`, кнопки в ней только значком (подпись в подсказке), списки сжаты. Если и так не влезает - правая часть уходит второй строкой.
- Контейнеры в `GUIRenderer` (`Accordion`, `Tabs` через сниппет `Content`) рисуют содержимое через `Layout`: уже 640 px - раскладка по группам `layoutFlow`, а не ячейки в сетке `size.width`.
- `Select type="buttons"` без `fitContent` сам становится выпадающим списком, когда варианты не помещаются; с `fitContent` не сворачивается никогда.
- Сворачиваемые разделы внутри виджетов - `SectionHead` с круглым значком `ExpandIcon`. В шапках виджетов и в `Accordion` круглого значка нет - там маленькая стрелка (решение владельца).
- `WidgetPFD` в компактном режиме (уже 440 px) рисуется 1:1 (ширина viewBox = ширина прибора). Карта без кнопок масштаба и местоположения (колесо и два пальца), панели поверх карты на узкой ширине короче.
- Проверка: кнопка «Телефон» в витрине (рамка 375 px) и временная страница в `src/routes/<новое имя>` с `GUIRenderer`/виджетами на 320-414 px; перед коммитом удалить.
- Новые компоненты на холсте конструктора: виджеты свёрнуты (`collapsed: true`), размеры по умолчанию в `defaults.ts` (`COMPONENT_SIZES`).

## Подводные камни разработки

- Vite держит старые модули: после удаления и создания файлов или правок в `node_modules` - перезапуск dev-сервера с очисткой `node_modules/.vite`, временную страницу называть каждый раз по-новому. Браузер кэширует модули с `?t=`; ошибки в консоли со старой меткой времени - это старый модуль.

## Выпуск

- Версия в `package.json`, выпуск сообщением коммита в `main`: `[publish]` - npm, `[deploy]` - витрина на GitHub Pages. Обычно оба: `X.Y.Z [deploy] [publish] ...`.
- После публикации CI сам ставит версию в DevCloud и выкатывает облако коммитом `X.Y [deploy] Обновление ElementsUI до X.Y.Z`. Вручную версию библиотеки в облаке не поднимать.
- После обновления зависимостей проверь `allowScripts` в `package.json`: версии там должны совпадать с установленными.
- После обновления `maplibre-gl` подними `MAPLIBRE_VERSION` в `src/lib/WidgetMap/mapWrapper/utils.ts` до установленной (сверяет `tests/maplibre.test.mjs`). Версия npm в `npm_publish.yaml` закреплена, поднимать вручную.

## Правила работы с пользователем

- Комментарии в коде только однострочные `/* ... */`, без истории «было/стало».
- Документация простым коротким русским языком, сверяется с кодом. Только текущее состояние: без истории, миграций, «было/стало» и упоминаний удалённого.
- Перед коммитом показать, что изменилось, и дождаться явного «коммить». Строк соавторства и подписей генерации в коммитах нет.
- Всё, что стало ненужным, удаляется сразу. Хлама не оставлять.
- В текстах обычный дефис "-", без длинных и средних тире.

## Документация и справочник для ИИ

- Стиль документации - как README компонентов ElementsUI: простой человекочитаемый язык для того, кто видит проект впервые (заголовок со значком, одна фраза о назначении, «✨ Что умеет», «🧩 Как пользоваться», «💡 Полезно знать»), а все тонкости и технические подробности - в сворачиваемых блоках `<details><summary>…</summary>…</details>`. Факты не теряются: техническое не удаляется, а уходит в блоки.
- Документация - часть изменения. Любая правка кода в том же коммите обновляет README затронутого компонента, руководства и этот файл, если меняются поведение, API, протокол, настройки, сборка или выпуск. Код без актуальной документации не коммитится.
- `KnowledgeBase-ElementsUI.md` в корне - справочник проекта для ИИ (внешняя база знаний), в нём всегда актуальная информация о проекте. Вручную его не правят: файл собирает `node .knowledgebase/build.mjs` из обзора `.knowledgebase/Overview.md` и всех `.md` файлов проекта под git (README, руководства; AGENTS.md - инструкции для агента - в справочник не входит).
- Справочник собирается сам: хук `.githooks/pre-commit` перед каждым коммитом запускает `node .knowledgebase/build.mjs --staged` (из того, что коммитится) и добавляет справочник в этот же коммит - коммит один, CI справочник не трогает. Хук включается в копии репозитория один раз командой `git config core.hooksPath .githooks`, это делает сам `npm install` (скрипт `prepare`). При смене архитектуры, стека, структуры, команд, протокола или правил сначала обнови `.knowledgebase/Overview.md`.
